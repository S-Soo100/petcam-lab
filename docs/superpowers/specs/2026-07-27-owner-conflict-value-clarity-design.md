# Owner 불일치 실제 값 비교 설계

## 목적

Owner 불일치 검수 화면이 `하이라이트 여부`, `촬영 환경`처럼 **다른 항목명만** 보여주고
라벨러 A/B가 각각 무엇을 선택했는지는 숨기는 문제를 해결한다. Owner는 DB나 별도 도구 없이
현재 화면 하나에서 차이를 이해하고 판정할 수 있어야 한다.

## 사용자 체험

- **[화면]** 영상 아래에 `서로 다른 항목`별 비교 행이 보인다.
- **[조작]** Owner가 영상을 재생하며 각 행의 `A 선택`과 `B 선택`을 대조한다.
- **[반응]** `행동 대상: 유리/벽 ↔ 일반 사물`, `하이라이트 여부: 제외 ↔ 포함`처럼 실제
  한국어 값이 즉시 보인다.
- **[감정]** 숨겨진 값을 추측하지 않고 확신을 갖고 A/B/새 판정을 고른다.

## 표시 계약

1. `differing_fields`에 포함된 항목만 비교 행으로 표시한다.
2. 각 행은 항목명, A 실제 값, B 실제 값을 같은 비중으로 보여준다.
3. enum·배열·구간은 기존 `labelingDisplay` 한국어 formatter를 재사용한다.
4. 빈 촬영 환경 배열은 라벨링 입력 문구와 같은 `해당 없음`으로 표시한다.
5. 알 수 없는 필드나 값은 내부 문자열 대신 `확인 필요`로 표시한다.
6. 기존 A/B 제출 요약과 판정 버튼, API, DB, consensus 계약은 변경하지 않는다.
7. 320px에서도 가로 스크롤 없이 줄바꿈되고 A/B 값의 대응 관계가 유지돼야 한다.

## 구성

- `_blind-review-view.ts`: 허용된 필드명과 A/B 값을 사람이 읽는 비교 행으로 변환하는 순수 함수.
- `_owner-conflict-comparison.tsx`: 비교 행을 반응형으로 렌더링하는 표시 전용 컴포넌트.
- `blind/conflicts/[clipId]/page.tsx`: 기존 항목명 전용 배너를 실제 값 비교 컴포넌트로 교체.

## 안전·검증

- API 응답, 인증, 제출·해결 mutation은 수정하지 않는다.
- 원본 `initial_gt`에서 `differing_fields` allowlist에 해당하는 값만 표시한다.
- 순수 formatter와 SSR 렌더 테스트를 RED→GREEN으로 고정한다.
- 전체 web 테스트, TypeScript, Python 회귀, Next production build를 실행한다.
- production 배포 후 Owner 상세 화면에서 실제 A/B 값이 보이는지 브라우저로 확인한다.
