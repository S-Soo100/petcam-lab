# 라벨링 웹 행동 표시 3종 — 의미있는 행동 · 쳇바퀴 · 추락

> 지금 ✨ 버튼 하나("의미있는 행동", 종류 없음)를 **종류 있는 표시 3개**로 넓힌다. 쳇바퀴는 GME 가 못 잡는 제자리 활동의 정답 세트, 추락은 안전 신호 세트가 되고, 셋 다 앱 대표 선정에 바로 반영된다.

## 1. 목적

- **팀원:** 버튼 하나로 "무슨 행동인지" 를 남긴다. 종류 판정 없이 3개 중 고르기.
- **유저(앱):** 쳇바퀴·추락처럼 GME 숫자로는 안 잡히는 영상이 아침 대표에 올라온다.
- **엔진:** 쳇바퀴 표시 = "제자리 활동" 정답 세트(대응안 4 의 데이터), 추락 표시 = 안전 신호 정답 세트. 둘 다 지금은 사람 눈으로만 모을 수 있다.

## 2. 스코프

### In

1. **표시 종류** `kind ∈ {meaningful(의미있는 행동), wheel(쳇바퀴), fall(추락)}`. 영상당 종류별 1개, 종류끼리 독립.
2. **DB** — `motion_clip_behavior_flags` 에 `kind` 컬럼(기본 `meaningful`, PK `(clip_id, kind)`), RPC `fn_get_motion_clip_behavior_flags(clip)`(종류별 행) · `fn_set_motion_clip_behavior_flag(clip, user, is_owner, kind, flagged)`. 기존 4-인자 set 은 `meaningful` 위임 wrapper(배포 순서 무관). 목록 함수는 `behavior_flagged`(어느 종류든) 유지 + `behavior_kinds text[]` 추가, 필터 `p_behavior_flag ∈ {yes, meaningful, wheel, fall}`.
3. **대표 선정(`fn_highlight_featured`)** — 사건 점수 정렬을 `추락 > (의미있는 행동 또는 쳇바퀴) > 사람 O > activity 합` 으로. **쳇바퀴 사건은 밤·카메라당 대표 최대 1**(`p_wheel_cap` 기본 1), **추락 사건은 상한 무시**(항상 featured). 출력에 `behavior_kinds`.
4. **앱 API** — 항목에 `behavior_kinds: ["wheel"]`(기존 `behavior_flagged` 유지).
5. **라벨링 웹** — 액션 바 버튼 3개(PC·모바일), 단축키 F/W/D, 목록 칩 3개(`?behavior_flag=wheel` 등), 카드 배지 종류별(✨·🎡·⚠️), 상세에 종류별 체크한 사람.
6. **문서** — 런북 §6.x 갱신, 슬랙 안내 문구, 앱 핸드오프 한 줄(아이콘 선택).

### Out

- 쳇바퀴·추락 **자동 검출** — 대응안 4·6(별도 스펙, 2.6.1 뒤).
- 종류 추가 UI(owner 가 종류를 늘리는 화면) — CHECK 제약 migration 으로만.
- 기존 ✨ 표시 데이터 재분류 — 전부 `meaningful` 로 남김. 쳇바퀴였던 건 팀원이 다시 눌러야 함(현재 ✨ 수가 적어 부담 없음).
- 추락 알림(푸시) — 안전 신호 세트가 쌓인 뒤 별도.

## 4. 설계 메모

- **왜 테이블을 새로 안 만들고 kind 를 붙이나:** 기존 ✨ 데이터(전부 meaningful)가 그대로 살고, 해제 권한(체크한 사람·owner)·적격 검사·멱등 INSERT 가 그대로. PK 만 `(clip_id, kind)` 로 넓힌다.
- **대표 선정 정렬:** 추락은 안전 신호라 최상위. 쳇바퀴와 의미있는 행동은 같은 급(둘 다 "사람이 볼 만하다고 한 것"), 그 안에서 사람 O·activity 로. 쳇바퀴 상한 1 은 "너무 많이 돌림" 대응 — 쳇바퀴 사건이 3개면 activity 합이 큰 하나만 대표, 나머지는 후보(더 보기).
- **시간당 3 상한과의 관계:** 추락은 무시, 쳇바퀴·의미있는 행동은 기존대로 시간당 3 안에서(대개 1위라 걸릴 일 없음).
- **앱:** `behavior_flagged` 는 계속 true/false 라 지금 앱은 무변경으로 동작. 아이콘은 선택(Q4).
- **하이라이트 O/X 와 무관** 원칙 유지 — 표시는 대표 선정과 정답 세트에만 쓰고 유지율·사유 통계에 안 섞는다(런북 §6.x).

## 5. 유저 체험 시뮬레이션

**팀원(PC)**
`[화면]` 영상 상세. 액션 바 위에 버튼 3개 한 줄: `✨ 의미있는 행동` `🎡 쳇바퀴` `⚠️ 추락`. 아래에 `O 확정` `X 확정`.
→ `[조작]` 쳇바퀴 도는 영상 → `W` 또는 🎡 탭 → 버튼이 "🎡 쳇바퀴 · 김라벨" 로 바뀜 → 이어서 `O` 확정.
→ `[반응]` 목록으로 오면 그 카드에 `🎡 쳇바퀴` 배지 + `⭐ 대표 1위`(그 밤 쳇바퀴 첫 사건이면).
→ `[감정]` "어떤 행동인지" 를 세 개 중 고르기만 하면 되니 판단 부담이 없다. 내 표시가 앱에 바로 반영되는 게 보인다.

**팀원(모바일)**
`[화면]` 하단 고정 바: 첫 줄 버튼 3개(엄지 크기, 아이콘+짧은 글자), 둘째 줄 O/X.
→ `[조작]` 추락 영상 → ⚠️ 탭 → `O` 탭.
→ `[반응]` 다음 영상으로 자동 이동. 그 밤 대표 1위가 됨.

**목록**
`[화면]` 칩 `✨ 의미있는 행동` `🎡 쳇바퀴` `⚠️ 추락` 각각 필터. `🎡 쳇바퀴` 켜면 쳇바퀴 표시된 영상만 — 이게 곧 "제자리 활동 정답 세트".

**유저(앱)**
`[화면]` 어젯밤 대표 안에 쳇바퀴 1장·추락 1장(있으면)이 들어 있음. 카드엔 아이콘만(Q4).
→ `[감정]` "오늘은 쳇바퀴 탔네", "떨어졌었네" 를 아침에 안다.

## 6. 학습 노트

- **종류 없는 플래그 → 종류 있는 플래그:** 처음엔 "종류 판정 부담을 없애자" 였는데, 종류가 3개면 판정 부담이 거의 없으면서 데이터 가치가 훨씬 커진다(정답 세트가 종류별로 생김). PK 확장만으로 옛 데이터를 보존한 채 넓힐 수 있다.
- **사람 신호를 대표 선정에 넣는 두 방식:** 최상위 고정(추락)과 상한 있는 우선(쳇바퀴). 빈도·중요도에 따라 다르게.
